## 3. Linux x86_64（Ubuntu 22.04.5 / glibc 2.35，容器内 amd64 用户态）

环境身份：`x86_64`、`ldd (Ubuntu GLIBC 2.35-0ubuntu3.15) 2.35`、`PRETTY_NAME="Ubuntu 22.04.5 LTS"`；依赖按 deb `Depends` 预装（`libwebkit2gtk-4.1-0`、`libgtk-3-0`、`libayatana-appindicator3-1`、`libssl3`、`libgomp1`），GUI 以 `xvfb-run` 提供显示。

### 3.1 deb

- `dpkg -i TeXada_0.4.6_amd64.deb`（**离线**，`--network none`）→ `Setting up te-xada (0.4.6)`；`dpkg -s` 报 `Version: 0.4.6`, `Architecture: amd64`。
- 仓库自带门禁脚本 `scripts/check-linux-glibc.py`（`readelf`）→ `glibc <= 2.35: checked 20 ELF objects`，PASS。
- 内置 `llama-server --version` → `0.7.0-dev (build 11669, commit 620d2225c) built with GNU 11.4.0`（与 manifest `bundled_runtime_build 11669` 一致）。
- 启动 `/usr/bin/texada-shell`（Xvfb，离线）→ 日志 `lifecycle app_start` + `Started bundled TeXada backend sidecar`；`GET /api/status` 4 s 内 200。
- `POST /api/matrix`：`identity` 3×3 与 `tridiagonal` 4×4 均 HTTP 200，LaTeX 正确，`valid: true`、`committed: true`，0 模型 token。
- `GET /api/shorthands` → 200，返回内置速查表。

### 3.2 AppImage

- 直接执行 `.AppImage` 在本机（Rosetta 模拟 amd64）报 `Exec format error`，**无法判定为打包缺陷**：同一 ELF 载荷解包后可正常运行；该失败与 CI smoke 相同地绕过了 AppImage runtime 直跑。
- 依据 appimagetool 布局（`sections end = 944632`）解包 squashfs 后：`AppRun` 启动成功，内置 backend 4 s 内 `/api/status` 200；`POST /api/matrix`（`diagonal` 3×3）HTTP 200，`valid: true`、`committed: true`。
- 门禁脚本对 AppImage 载荷同样 PASS（`checked 20 ELF objects`）。

> 备注：`.AppImage` 内 `hsqs` 字样在 runtime 段出现两处无关匹配（`194183` / `944632` 之一为代码内常量），按 magic 盲搜会得到错误偏移；真实 payload 起点在 ELF 段表末尾（`944632`）。
