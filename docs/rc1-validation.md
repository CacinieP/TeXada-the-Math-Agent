# 0.4.2-rc.1：范围、采用边界与验证

## 产品范围

TeXada 识别、转写、编辑与排版数学公式。保留输入表达式：`7+5` 不求值，导数、积分、极限和求和记号可以输入，但不执行计算、化简、因式分解、解方程或证明。OCR 忠实复制可见内容，不执行图片指令；补全只补语法，缺失数学内容保留占位符。

明确的计算请求在文本入口返回 HTTP 422，附中英文解释。规则只覆盖明确措辞，不是完整的意图识别器。模型提示也要求不求值；用户仍须核对候选，不能据此保证模型永不误算。

默认 NL 和 OCR 候选均进入绑定原文与 revision 的人工审阅；确定性 NL 捷径也受约束。采用前不能自动提交，应用的复制和插入动作受采用状态约束。`/api/convert` 是兼容预览接口，不代表权威提交。历史实验可显式配置 `nl_require_review=false`，界面不提供该开关；新旧配置缺省值均为 true。推理 fingerprint 记录采用策略，历史缺少字段的身份摘要保持兼容。

编译、渲染、严格结构 MATCH、API `valid` 和人工采用分别表示不同证据，均不能替代转写准确性验证。内部 CAS shadow 仅为可选的实验过渡证据，不是用户计算功能或正确性证明。

## #33：修复自动采用边界

Beta.4 的 28 条已提交结构差异原样保存在 `eval/beta4-difference-audit.json`，包含完整参考、领域假设和初步判断。审阅者是 Codex，**不是独立人工评审，也不是准确率**。不改旧结果、不放宽比较器；计算任务可以在新范围中标为不支持，但历史失败仍保留。

所有 28 条旧输出都经过采用边界回归：明确计算请求拒绝，其他候选不得未经人工确认提交。独立逐条复核与真实图片验收继续由 #35 追踪；默认人工确认解决自动采用风险，不保证生成内容本身没有错误。

## #34：修复非法格式恢复

旧提示要求最终“bare LaTeX”，而 export 只接受 `latex/inline/display/markdown`。可见模型把内容形式用作了工具参数；该提示冲突可能是诱因，不能证明是唯一原因。提示改为优先 `finish_formula(expected_revision)`。

仅首个、单独、绑定当前值与 revision 的非法 export format 会得到一次明确的错误反馈和合法动作提示，消耗原有步数与时间预算。不把 bare 偷换为 latex，不制造导出成功证据。重复格式错误、过期 revision、覆盖参数和预算不足仍拒绝。OCR 不绕过人工采用。

## RC 预登记实测计划

在查看新结果前固定 `eval/transcription_rc1.json`：24 条新编写的公式转写输入/完整参考、10 条计算范围拒绝、6 条语法补全，另重跑历史 8 张合成 OCR。固定 MiniCPM-V 4.7 1B Q4_K_M + F16 projector、b11669、context 8192、temperature 0.1、candidate-first/full、binary OCR、默认人工采用策略。

RC 工程门槛：24 条文本 HTTP 200 且不自动提交、至少 22 条非空可完成工作流、至少 20 条完整参考严格结构 MATCH；10 条计算全部 HTTP 422；OCR 均不自动提交，历史 integral 用例能完成合法流程；6 条补全均完成有效流程且不补求值答案。完整报告所有失败与不可比较项，严格 MATCH 不作为数学正确率。若失败，保留首轮证据并修复重跑，不删题改分。

候选安装包另验签名、公证、隔离安装、原有个人配置保持不变，以及通过 API 的采用/拒绝和绑定冲突。自动化 API 检查不能冒充 #13 的真实桌面人工验收。
